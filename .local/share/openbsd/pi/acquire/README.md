# Portable source acquisition

Run `node prepare.mjs /absolute/new-build-inputs` as the ordinary user. The destination must not exist and its ancestors must be trusted directories. This does not install, activate, sign in, or change a live profile.

`inputs.json` binds exact source-owned manifests and locks. Pi is 1.6.0; esbuild is a separate build-only 0.25.5 project. Board production dependencies are a separate exact manifest/lock containing node-pty 1.1.0, headless xterm 6.0.0 and their admitted transitive closure. No Pi SDK or development tools are delivered inside Board. The original upstream manifest/lock remain immutable source evidence, not the production dependency contract. Board SDK/typecheck qualification must use the selected generation's SDK. Deliberate supported-version upgrades require new admitted resolution and qualification, not permanent lifetime version restrictions.

npm resolution and ci use the canonical qualified admission implementation with lifecycle scripts disabled. A complete nonmalicious graph (clean or reported advisories), clean signatures, and clean scanner gates are mandatory before receipt publication or dependency execution. Unknown/malicious graphs and nonclean signatures/scanner results fail closed. Timeouts do not constitute completed scans and never produce successful receipts.

Successful output is `roots.json`, containing pristineRoot, boardRoot, messengerRoot, and toolRoot. Board layout is `board/source` (unpatched pinned Git checkout), `board/dependencies/project` (untouched admitted production dependencies), and `board/build/project` (independent native build copy). The native build receipt is `board/build/receipt.json`; registry receipts sit beside each acquisition project. toolRoot is the actual `tool/project/node_modules/esbuild` directory; its receipt covers the entire tool project, including the optional platform binary sibling. Messenger is staged from pinned public source using the retained exact staging manifest and patch. Resource/profile inputs remain separate and are not implicitly copied from HOME.

Registry receipts bind source manifest/lock digests, canonical admission identity and qualification, the full file/mode/link inventory, and hashes of graph/signatures/scan evidence. Signature and scan evidence bind unchanged pre/post inventory, exact project, manifest, lock, and private execution times. These are per-attempt receipts, not public baseline approval or cross-machine golden trees. Native qualification here is only addon load and shell PTY exit; Board API/executed graph qualification is separate. Child execution timeouts do not guarantee process-group cleanup or bound disk log size.

Projection explicitly excludes only publishConfig equal to {"access":"public"}, the pinned Board's publish-only access metadata; other publish controls are refused. The production contract intentionally excludes upstream development SDK and optional host peers rather than pruning an installed dependency tree.

Run `node --test test.mjs` for synthetic safety controls. Actual acquisition, native compilation and selected-host qualification are additional evidence and are not replaced by fixture tests. Locks alone do not establish completed security gates or a qualified pristine baseline.
