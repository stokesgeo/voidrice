# Outcomes, evidence and handoffs

Prefer deterministic checks where they can establish the claim. Check the
actual files/service/device boundary, not only a remembered write or successful
command. Exercise the real provider and physical machine where the outcome
depends on them; a protocol check does not establish a model's judgment.

Cold review is useful for costly false confidence where no deterministic check
exists; supply only the artifact and question. It does not prove completeness,
and user choices remain the user's. Keep review proportionate to the risk.

A handoff carries task identity, work object, changed paths, checked evidence,
hazards and the remaining next action. The parent verifies the return before
closing the durable task. Subagent success is not parent acceptance; a queued
or finished subprocess is not a delivered outcome. Unfinished required work
keeps its owner and next action visible.

Completion evidence strings in a record are model-authored claims. The tool
checks their presence, not their truth. Perform the referenced checks before
recording completion; never describe schema validation as independent proof.
